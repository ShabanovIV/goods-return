# Goods Return

## Базовый путь приложения

В `.env` задайте путь размещения приложения без домена и порта:

```dotenv
APP_BASE_PATH=/goods-return/

# Равнозначные варианты:
# APP_BASE_PATH="goods-return"
# APP_BASE_PATH=goods-return
```

Начальный и конечный `/` добавляются автоматически: `goods-return` и
`/goods-return/` равнозначны. Допустимы вложенные пути, например `/services/claims/`.
Если переменная отсутствует, пуста или равна `/`, приложение работает от корня сайта.

После изменения `.env` перезапустите `npm start` или заново выполните `npm run build`.
Значение встраивается в сборку: изменение `.env` рядом с готовыми файлами не изменит их.

При `APP_BASE_PATH=/goods-return/`:

- локальное приложение открывается на `http://localhost:3000/goods-return/`;
- документ доступен на `/goods-return/invoices/<documentId>`;
- JS, CSS и ресурсы сборки загружаются из `/goods-return/`;
- кнопка «На главную» на экране ошибки возвращает в `/goods-return/`.

## Публикация в подпапке

1. Задайте `APP_BASE_PATH` и `PRODUCTION_API_URL` в `.env` или окружении сборки.
2. Выполните `npm run build`.
3. Настройте сервер на раздачу содержимого `dist` по выбранному URL-префиксу.
4. Настройте SPA fallback: маршруты приложения, например
   `/goods-return/invoices/123`, должны возвращать `/goods-return/index.html`.
   Существующие статические файлы и запросы API не должны попадать в этот fallback.

Например, документ будет доступен по адресу:

```text
http://my.test.com:5000/goods-return/invoices/123
```

Само значение `APP_BASE_PATH` не настраивает сервер и не создаёт подпапку в `dist`.
Настройки `DEVELOPMENT_API_URL` и `PRODUCTION_API_URL` независимы от пути приложения.
Для API используйте полный URL или путь от корня сайта, например /api/.
Во втором случае браузер использует протокол, хост и порт текущей страницы.
Сервер должен обслуживать API по этому пути либо проксировать запросы на бэкенд.
Если API находится на другом хосте или порту и прокси не настроен, укажите полный URL.
